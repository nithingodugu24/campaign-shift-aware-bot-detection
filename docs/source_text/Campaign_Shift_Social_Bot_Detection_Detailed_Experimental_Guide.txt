DETAILED EXPERIMENTALIMPLEMENTATION GUIDE
Campaign-Shift-Aware Social Bot Detection with Temporal Coordination Modeling and Selective Prediction
Student-facing guide for dataset preparation, baseline implementation, experiments E1–E8, evaluation, and reportingPrepared to support implementation of the paper's experimental protocol

How to use this document
This guide translates the paper's experimental plan into a practical implementation workflow. It explains what data are needed, what each experiment tests, which methods should be compared, how to run the experiment, which metrics to calculate, and what files and tables to submit.
Important: this is an implementation protocol, not a results document. Do not invent, estimate, or copy numbers into result tables. Fill every result only after running the corresponding experiment. If a dataset does not contain a required field or a baseline cannot be reproduced, document that limitation and discuss it with the supervisor.
Project objective
Test whether a social bot detector that models temporal coordination and uses campaign-aware selective prediction is more reliable under campaign shift than conventional account-feature, graph-based, and confidence-calibration baselines.
Research questions
RQ1: Does performance measured with random account splits overestimate performance on unseen campaigns or later time periods?
RQ2: Does temporal coordination modeling add value beyond account profiles and static graph structure?
RQ3: Does null-model correction reduce spurious coordination links caused by activity level or chance co-activity?
RQ4: Does campaign-aware calibration improve the reliability of prediction sets or abstention decisions at group level?
RQ5: What accuracy–coverage trade-off is obtained when the detector can abstain on uncertain cases?
RQ6: How robust is the approach to missing events, timestamp perturbations, benign synchronization, and dataset changes?
RQ7: What are the computational costs of graph construction, null estimation, training, calibration, and inference?

2.1 Dataset audit checklist
Record dataset name, version, download date, citation, license, and original source.
Count accounts, labels by class, events, edges, groups, and timestamps.
Report missing-value percentages and duplicate rows/events.
Check for overlapping account IDs across train/validation/calibration/test splits.
Check whether labels, group identifiers, or features were created using future information.
Record whether group/campaign labels are verified or inferred.
Do not call a connected component or inferred community a verified campaign unless evidence supports that description.
Freeze and save the cleaned dataset manifest before training models.
3. Data leakage prevention and split protocols
The paper's central claim concerns campaign shift. Therefore, split design is part of the scientific contribution, not a minor implementation detail. Every comparison must use the same eligible accounts and split definitions wherever possible.
Protocol
Construction
Main purpose
Caution
P0: Random account split
Randomly split accounts into train/validation/calibration/test using a fixed seed; preserve class balance where feasible.
Conventional reference benchmark.
Related accounts/events can leak across splits; do not treat as the main evidence of shift robustness.
P1: Campaign/group-disjoint
Assign whole verified campaigns/groups to one split only. No group may appear in more than one split.
Tests generalization to unseen groups.
If verified campaign labels are unavailable, state that the groups are proxies/inferred.
P2: Repeated group holdout
Repeat group-disjoint evaluation over several independently chosen held-out group sets.
Measures variability across held-out groups.
Independent unit is the group/campaign, not each random seed alone.
P3: Chronological
Train on earlier data; validate/calibrate on later but non-overlapping periods; test on the latest period.
Tests temporal drift.
Features must use only information available at prediction time.
P4: Cross-dataset
Train and tune on source dataset; evaluate on a compatible target dataset without target-label tuning.
Tests external generalization.
Align label definitions and feature availability; disclose all incompatibilities.

3.1 Split rules
Create splits before fitting scalers, imputers, feature selectors, graph thresholds, or calibration models.
Fit data-dependent preprocessing on training data only; apply the fitted transformation to validation/calibration/test.
Use validation data for model selection and calibration data for calibrator fitting. Keep the test set untouched until final evaluation.
If the proposed method uses group-level calibration, keep entire groups in the calibration partition and follow the method's exact requirements.
Save the IDs assigned to each partition so every baseline uses the same split.
Report class distribution and number of groups in every split.
Run multiple seeds or repeated group holdouts where feasible; do not claim that seeds create additional independent campaigns.

Method
Purpose
Key rule

Formal coverage guarantees depend on the exact method and assumptions. Do not state that arbitrary campaign shift is covered by a standard conformal method unless the theorem and assumptions actually justify it. Report empirical coverage separately from theoretical guarantees.

Size of returned label sets.

Fraction receiving one-label prediction.

Fraction withheld from automatic prediction.
Report alongside selective accuracy and coverage.
Selective accuracy
Accuracy on non-abstained examples.
High accuracy can be achieved by abstaining on most cases; always report coverage.
Runtime and memory
Scalability.
Measure graph building, null estimation, training, calibration, and inference separately.

5.1 Statistical reporting
Report mean and standard deviation across repeated runs, where runs are appropriate.
For independent group/campaign comparisons, use the group as the statistical unit where justified.
Use paired comparisons when methods are evaluated on the same groups/splits.
Report confidence intervals and the number of independent groups supporting them.
Avoid treating accounts within one campaign as independent evidence of generalization to new campaigns.
Predefine the primary metric and primary split before inspecting final test results.
Keep full metric tables, not only the best scores, and disclose failed runs or exclusions.
6. Experiment E1 — Random versus campaign-shift evaluation
Objective
Determine whether conventional random account splitting gives an overly optimistic estimate of performance compared with evaluation on unseen groups/campaigns or later periods.
Methods
RF, SVM, GraphSAGE, BotRGCN, and the proposed detector. Use the same split definitions for all compatible methods.
Procedure
Prepare P0 random, P1 group-disjoint, and P3 chronological splits if the data supports them.
Train each method on the training partition and select settings using validation data.
Fit calibration only on the designated calibration partition if the method requires calibration.
Evaluate once on the test partition for each protocol.
Repeat with multiple seeds and/or repeated group holdouts where feasible.
Calculate Macro-F1, PR-AUC, ROC-AUC, MCC, and FPR.
Calculate the performance drop from P0 to P1/P3 for each method and show uncertainty.
Required outputs
Table: each model × split protocol × metric.
Figure: performance by split protocol with uncertainty bars.
Figure/table: random-to-group-disjoint performance change.
Short interpretation: which methods degrade most, and whether the proposed method reduces the degradation.
Do not assume that campaign shift exists or that your model solves it. Establish the effect empirically; if the result is weak or inconsistent, report that honestly.
7. Experiment E2 — Contribution of temporal coordination
Objective
Test whether temporal co-activity/coordination features improve detection beyond account profiles and static graph structure.
Variants
A1 profile-only; A2 profile + rhythm; A3 profile + static graph; A4 profile + temporal graph; A7 full model. Compare BotDGT/BotSTIP or TGN/TGAT where reproducible and compatible.
Procedure
Freeze the split protocol, preferably including P1 and P3.
Use the same train/validation/test IDs for every ablation.
Hold optimization budget and model-selection policy as consistent as possible.
Train each variant and evaluate Macro-F1, PR-AUC, ROC-AUC, MCC, and FPR.
Compare the full model with each reduced variant and calculate absolute changes in the primary metrics.
Inspect performance by group to see whether temporal features help broadly or only in a few groups.
Required outputs
Ablation table with all variants and metrics.
Bar chart or dot plot showing metric differences relative to profile-only.
Description of the exact temporal features and interaction records used.
Caution: temporal models may have more parameters and richer inputs than classical baselines. Disclose input differences and provide fair ablation comparisons.
8. Experiment E3 — Campaign-aware calibration and group reliability
Objective
Evaluate whether calibration that respects campaign/group structure produces more reliable predictions than ordinary confidence thresholding or account-level calibration.
Methods
Maximum-softmax threshold; temperature scaling plus threshold; account-level split conformal; campaign/group-blocked calibration; proposed campaign-unit calibration.
Procedure
Choose the detector and freeze its trained parameters before fitting calibration methods.
Partition calibration groups separately from training and test groups.
Fit each calibrator using only its designated calibration data.
Specify target coverage/error level and calibration score before running test evaluation.
Evaluate pooled empirical coverage, mean prediction-set size, singleton rate, and group-level miscoverage.
Report the distribution of per-group miscoverage (e.g., median, interquartile range, and worst observed group) when the number of groups supports it.
Repeat group holdouts where feasible and report uncertainty.
Required outputs
Calibration table with coverage, group miscoverage, mean set size, and singleton rate.
Reliability plot or group-wise miscoverage plot.
Statement of each method's assumptions and whether those assumptions are plausible in the experiment.
A method's observed coverage on one test set is empirical evidence, not by itself a universal or distribution-free guarantee under campaign shift.
9. Experiment E4 — Null-model correction and graph ablation
Objective
Test whether the proposed null-model correction prevents chance co-activity or high activity volume from producing misleading coordination edges.
Variants
No graph; static/shared-object graph; temporal graph without null correction; temporal graph with null correction; corrected graph with the proposed filtering/sparsification.
Procedure
Use identical account sets, time windows, and train/test partitions.
Record graph nodes, edges, density, degree distribution, and edge-weight distribution for each variant.
Apply null correction using only the information permitted by the paper's definition; avoid test-label information.
Train the same downstream detector for each graph variant.
Evaluate detection metrics and computational overhead.
Check whether correction disproportionately removes edges from high-activity accounts or specific groups.
Required outputs
Graph statistics table before and after correction.
Detection ablation table.
Runtime comparison for graph construction and null estimation.
Example visualizations of graph structure, only if they can be produced without exposing private user data.
Caution: define the null model, sampling procedure, significance/threshold rule, and random seed in advance. Do not select the graph threshold using test labels.
10. Experiment E5 — Selective prediction trade-off
Objective
Measure whether the system can increase reliability on automatically classified accounts by abstaining on uncertain examples, and quantify the cost of abstention.
Methods
Confidence threshold; temperature-scaled confidence threshold; account-level conformal method; campaign-aware method; proposed selective predictor.
Procedure
Select thresholds or target operating points on validation/calibration data only.
Sweep a predeclared range of confidence thresholds without test-driven tuning.
At each operating point, record the fraction automatically classified, abstention rate, selective accuracy, FPR among automatic decisions, and prediction-set properties if applicable.
Plot selective risk/accuracy against coverage or automatic-decision rate.
Compare methods at similar coverage levels where possible.
Report whether reliability improvements are obtained only by abstaining on a very large fraction of accounts.
Required outputs
Selective risk/accuracy versus coverage plot.
Table comparing methods at matched coverage levels.
Explicit definition of how empty or multi-label prediction sets are handled.
Do not report selective accuracy without the corresponding coverage/abstention rate. A model that predicts only a few easy cases may have high selective accuracy but limited utility.

12. Experiment E7 — Computational scalability
Objective
Quantify the computational cost of the full pipeline and identify which components dominate runtime and memory.
Measurements
Raw-data loading and preprocessing time.
Feature extraction time.
Temporal graph construction time and number of edges.
Null-model estimation/correction time.
Model training time per epoch and total training time.
Calibration time.
Inference latency per account or batch, with batch size specified.
Peak CPU/GPU memory and hardware/software configuration.
Procedure
Record CPU, GPU (if any), RAM, operating system, Python version, framework versions, and thread settings.
Run timing experiments under documented conditions; avoid comparing timings measured on different hardware without qualification.
Measure each pipeline component separately and report whether warm-up runs were excluded.
Evaluate multiple dataset sizes or graph sizes if the available data supports them.
Report runtime and memory together with predictive performance.
Required outputs
Runtime table by component.
Runtime versus number of accounts/edges plot where multiple sizes are available.
Memory-use table and a short bottleneck analysis.
13. Experiment E8 — Cross-dataset generalization
Objective
Test whether the trained detector transfers to a separate dataset without tuning on target labels.
Procedure
Select a source and target dataset with compatible bot/human labels and overlapping feature definitions.
Train and tune on the source dataset only.
Document any feature mapping and exclude target-only features unless the protocol explicitly supports them without label leakage.
Evaluate on the target dataset without fitting hyperparameters or thresholds to target test labels.
If target calibration is studied, define it as a separate adaptation experiment and disclose the target calibration data.
Report detection metrics, calibration/selective metrics where valid, and feature incompatibilities.
Required outputs
Source-to-target results table.
Feature/label compatibility table.
Limitations explaining dataset differences and any preprocessing required.
If datasets have incompatible labels or feature semantics, do not force an invalid direct comparison. Report the incompatibility and choose a defensible alternative.

15. Recommended implementation order
Stage 1 — Audit data and confirm that the key fields for labels, timestamps, interactions, and group splits exist.
Stage 2 — Implement a clean baseline pipeline with RF and SVM and validate all metrics/splits.
Stage 3 — Implement GraphSAGE/BotRGCN or the most compatible graph baseline.
Stage 4 — Implement profile and rhythm feature extraction, then static and temporal graph variants.
Stage 5 — Implement the full proposed detector and run the E1/E2/E4 ablations.
Stage 6 — Implement calibration/selective prediction baselines and run E3/E5.
Stage 7 — Run robustness and scalability tests (E6/E7).
Stage 8 — Run cross-dataset generalization (E8) if compatible data are available.
Stage 9 — Re-run selected experiments for repeatability, calculate uncertainty, and prepare final tables/figures.
Stage 10 — Write the report, including failed runs, exclusions, assumptions, and limitations.

19. Common mistakes to avoid
Using a random split alone to claim campaign-shift robustness.
Allowing the same campaign/group to occur in both training and test sets when claiming group-disjoint evaluation.
Fitting feature normalization, feature selection, thresholds, or calibration using test data.
Using future events to create features for earlier prediction times.
Comparing models with different information inputs without explaining the difference.
Treating inferred communities as verified campaigns.
Reporting only accuracy or ROC-AUC for an imbalanced dataset.
Reporting selective accuracy without coverage/abstention rate.
Calling empirical coverage a formal guarantee.
Claiming a baseline was reproduced when its implementation was substantially modified.
Reporting one best seed without variability or a rationale.
Inventing results, citations, or baseline scores.

21. Suggested starter references to verify
Use the original papers and official implementations for each method. Verify bibliographic details, versions, dataset availability, and licensing before citing or implementing. The list below identifies method families, not a substitute for checking the original source.
GraphSAGE: inductive representation learning on large graphs.
BotRGCN: heterogeneous graph neural network approach to social bot detection.
TGN and TGAT: temporal graph learning methods for timestamped interactions.
BotSTIP: spatio-temporal/hypergraph-based social bot detection; verify exact paper and code.
BotDGT: dynamic graph transformer approach; verify exact paper and code.
Split conformal prediction and temperature scaling: use original method papers and implement the precise score/quantile/calibration rules.
Final instruction to the student
The goal is not to make the proposed method win every table. The goal is to conduct a fair, reproducible evaluation of the paper's claims. If a result contradicts the hypothesis, report it, investigate it, and discuss its implications. A transparent negative or mixed result is scientifically stronger than an unsupported claim.
