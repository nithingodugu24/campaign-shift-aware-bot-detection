# Campaign Shift Aware Social Bot Detection

This project implements the supplied experimental protocol and provides executed public-data pilots, a collection-holdout study, and a separate synthetic validation suite. The numerical results are generated by the code. The current pilots do **not** establish that the proposed detector outperforms classical models or generalizes to verified unseen campaigns.

Start with [the project report](output/Project_Report.md), then inspect the CSVs in `results/`. The PDF version is in `output/Project_Report.pdf`. Run `python -m scripts.build_report_content` after changing results to regenerate the text report.

## What is included

- Audited CSV ingestion, UTC timestamps, duplicate and future-event checks, file hashes and missingness reports.
- Training-only imputation and scaling; profile, weekly rhythm, inter-event and spectral features.
- Shared-object, temporal, null-corrected and support-filtered mutual top-k graphs. A constrained object/day timestamp-permutation null preserves object timestamp distributions and account/object/day event counts.
- RF, SVM, logistic regression, a full-neighborhood GraphSAGE mean-aggregator implementation, group-DRO, equal-group reweighting, five controlled neural ablations and a relational proposed model. These are local research implementations; GraphSAGE is not an official-code benchmark reproduction.
- Confidence abstention, temperature scaling, account split conformal, group-maximum split conformal and campaign-unit conformal risk calibration. Infeasible calibration is explicitly flagged; the fallback abstains on all accounts.
- E1-E8 experiment orchestration, three seeds, genuinely distinct repeated P2 holdouts, saved split manifests, checkpoints, predictions, per-group metrics, uncertainty, paired exploratory statistics and Holm correction.
- Frozen-model missing-event and timestamp tests, activity/group-size strata, CPU runtime/RSS measurements and compatible profile-only external transfer.
- Standalone inference on labeled or unlabeled CSV accounts, tests, charts, result tables and an evidence-based report.

## Evidence and limits

| Study | Data | Purpose | Limits |
|---|---|---|---|
| `results/public` | Cresci-2017 bounded sample | Real P0 baseline, graph/temporal ablations, calibration, E6/E7; profile-only transfer to Gilani | One human collection prevents four-way P1/P2; no historical profiles for P3 |
| `results/collection` | Cresci-2017, Cresci-2015 and a bounded Gilani sample | P0/P1/P2 collection holdout; E2-E7; profile-only RTbust transfer | Collection proxies, overlapping collection history, heterogeneous event availability, few human groups; not verified campaigns |
| `results/synthetic` | Explicitly generated source and shifted target | Exercise P0-P4 and all E1-E8 code paths, including chronological and benign-synchronization tests | Designed fixture; never evidence about real social bots |

Real P3 remains unsupported because historical feature availability is unverified. External targets contain user snapshots, so temporal and graph models are excluded from real E8. BotRGCN, RGT, TGN/TGAT, BotDGT, BotSTIP and IRM are listed as not reproduced, with reasons; they are not silently relabeled implementations. Empirical coverage is not a guarantee under arbitrary campaign shift. Automatic labels are research outputs for review, not verified allegations about account owners.

## Setup

Use Python 3.11 or newer. These commands are for PowerShell from the project folder:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pytest -q
```

`requirements.lock.txt` records the exact environment used for the supplied runs. The tested accelerator is CPU. Sparse operations use PyTorch directly, so PyTorch Geometric is not required. The default pilot uses 50 maximum epochs, validation early stopping, two learning rates, eight null permutations and three seeds. It is a feasibility pilot, not an exhaustive hyperparameter search or a full-benchmark replication. `configs/default.yaml` supplies a larger 80-epoch/16-permutation configuration.

## Reproduce the experiments

Downloads total about 700 MB. Keep the original research-use disclaimers. Raw archives and the virtual environment are excluded from the packaged project. Prepared pilot tables and their licenses are included. Public access is read-only; no platform API, login or author contact is used.

```powershell
.venv\Scripts\python.exe -m scripts.prepare_public_data
.venv\Scripts\python.exe -m scripts.prepare_snapshot_targets
.venv\Scripts\python.exe -m scripts.prepare_collection_pool
.venv\Scripts\python.exe -m scripts.prepare_synthetic
.venv\Scripts\python.exe -m src.run_experiments --data data/processed/cresci2017 --target data/processed/gilani-2017 --config configs/pilot.yaml --output results/public
.venv\Scripts\python.exe -m src.run_experiments --data data/processed/collection_pool --target data/processed/cresci-rtbust-2019 --config configs/collection.yaml --output results/collection
.venv\Scripts\python.exe -m src.run_experiments --data data/processed/synthetic_source --target data/processed/synthetic_target --config configs/pilot.yaml --output results/synthetic
.venv\Scripts\python.exe -m scripts.analyze_results results/public results/collection results/synthetic
.venv\Scripts\python.exe -m scripts.build_report_content
```

`run_all.ps1` executes these commands sequentially with logging and stops on failure. It reruns experiments and overwrites matching output files, so use separate output paths if retaining an earlier study. Separate calibration/test label boundaries are enforced by the runner. Do not choose new settings after examining test outcomes and describe them as confirmatory.

## Use a saved model

Inference requires `accounts.csv` and `metadata.json`; `events.csv` and `edges.csv` may be empty. Labels can be omitted. Real data without event histories should use a compatible profile model, such as RF.

```powershell
.venv\Scripts\python.exe -m src.predict --run results/public --split P0_s11 --model RF --data data/processed/gilani-2017 --output output/my_predictions.csv
```

Output contains probabilities, two prediction-set membership flags and `human`, `bot` or `needs_review`. Infeasible or uninformative calibration can result in every account receiving `needs_review`. A batch constructs graphs only among its own accounts. Changing the batch changes graph context, so reproduce a held-out prediction with exactly the saved test partition. Load only trusted project checkpoints; pickle is not a safe interchange format for untrusted files.

## Input schema

- `metadata.json`: `name`, `data_kind` (`real` or `synthetic`), `group_type` (`verified_campaign`, `proxy_collection`, `synthetic`, `unavailable`), source/license and `chronology_supported`.
- `accounts.csv`: unique string `account_id`, binary `label` for experiments, `group_id`; numerical `followers`, `following`, `statuses`, `listed`, `verified`, `default_profile`, `description_length`. Missing profile fields are explicitly imputed with missingness flags.
- `events.csv`: `event_id,account_id,timestamp,object_id,action`. Multiple object records can represent one physical event. Rhythm extraction counts unique events; robustness perturbations treat all object records of a physical event together. Object identifiers must come from observable content or interactions, never labels or campaign IDs.
- Optional `edges.csv`: `source,target,relation`; supported relation is directed `follows`.
- Chronological data also require per-account `prediction_at` and `profile_observed_at`, both UTC-compatible, and a defensible account observation protocol. Account creation time is not an observation cutoff.

Raw numerical IDs are read as strings to avoid rounding. Processed public data omit screen names, profile descriptions and tweet text; shared objects are hashed. Public IDs still identify accounts, so preserve research-use restrictions.

## Protocols and statistical interpretation

The guide's numbering is authoritative in code: P0 stratified account random; P1 four-way group-disjoint; P2 repeated group holdout with seed offset 10000; P3 strict chronological account observation; P4 external transfer. The manuscripts use a different numbering for chronological/transfer protocols; see `docs/REQUIREMENTS.md`.

Every model uses the same eligible accounts and saved partitions. Graph construction and message passing occur independently within train, validation, calibration and test. No test labels enter scalers, models, thresholds or graph construction. P0 can share group identity across partitions and therefore supplies no independent-campaign calibration guarantee. P1/P2 do not establish exchangeability.

When observation cutoffs are supplied, graphs also exclude edges between different prediction times. This prevents a later account's profile or event history from reaching an earlier account through message passing. Align accounts to a shared observation cutoff when batch graph context is intended. All-unknown cutoffs retain the explicitly non-chronological offline batch setting.

PR-AUC means scikit-learn average precision with bot=1. ECE uses ten equal-width confidence bins. Both empty and two-label sets abstain; selective accuracy is undefined with no accepted accounts. Single-class ROC/AP and zero-denominator MCC/FPR are missing, never favorable constants. Per-run intervals resample whole declared groups and require at least five groups. Run standard deviations measure variation across seeds/splits, not independent campaign uncertainty. Paired exploratory tests first average repeated observations per group and apply Holm within the three predefined model comparisons; collection dependence and reused training sets remain limitations.

The campaign CRC criterion is `(sum_g L_g(q) + 1)/(K + 1) <= alpha` for the predeclared grid `q=0,0.001,...,1`, with `L_g` the mean miscoverage within a calibration group. Its finite-sample floor is `1/(K+1)`. No feasible grid point is silently substituted as a successful calibration. Full-set fallback has no automatic labels. `group_max_conformal` instead calibrates each group's maximum nonconformity score; it is a distinct, usually conservative group-coverage baseline.

## Outputs

The [experiments directory](experiments/README.md) contains one folder for each experiment E1-E8. Each has its own instructions, public/collection/synthetic results, figures, status and export manifest. The canonical shared checkpoints and split manifests remain under `results/`. Run `python -m scripts.organize_experiments` to refresh all experiment folders after rerunning studies.

`results/<study>/metrics.csv`, `group_metrics.csv`, `graph_statistics.csv`, `calibration.csv`, `selective_curves.csv`, `runtime.csv`, `experiment_status.csv`, `splits/`, `checkpoints/`, `tables/` and `figures/` contain the full evidence. `configuration.json`, `environment.json`, input SHA-256 hashes and the final `output/manifest.json` record provenance. The report's abbreviated tables do not replace the CSVs.

Dedicated E7 measurements were repeated with one experiment worker. Initial training timings may include contention from other experiment processes. RSS is sampled every 10 ms and includes native allocations and previously loaded libraries; it is process memory, not GPU memory or theoretical per-model storage.
